# Приклад прийому компанії: номенклатура з 1С

`nomenclature_1c.csv` - вивантаження довідника «Номенклатура» вигаданої компанії ТОВ «Приклад
Виробництво»: 105 рядків, кодування Windows-1251, роздільник «;», над таблицею рядок з назвою.
Так виглядає типовий довідник виробника після кількох років у 1С:

- той самий виріб записано по-різному: «Болт М8х30 DIN933 8.8 оц», «болт оцинк. M8*30 кл.8,8
  DIN 933», «Болт DIN 933 M8x30 8.8 Zn»;
- частина назв російською: «Сверло», «Подшипник», «Кольцо уплотнительное»;
- у деяких назвах бракує головного: «Пруток ф40» без марки, «Кутник 63х6» без матеріалу;
- поруч з комплектуючими - папір, послуги, рукавиці.

Після розбору (тест `test_11_intake_example_from_1c`): 58 різних виробів, 39 рядків - дублі,
5 рядків треба доповнити вручну, 8 - не комплектуючі. Болт DIN 933 і болт ГОСТ 7798 тих самих
розмірів лишаються різними товарами: це аналоги з перевіркою, а не дублі.

## Порядок прийому

1. **Вивантаження з 1С.** Довідник «Номенклатура» → «Вивести список» → зберегти як Excel чи CSV.
   Потрібні колонки: код, найменування, одиниця. Групи довідника не потрібні.
2. **Розбір.** Закупівлі → Комплектуючі → Розбір номенклатури → Створити, «Файл з 1С чи Excel»,
   «Розібрати». Документ показує, скільки розібрано, скільки дублів і чого бракує.
3. **Перегляд.** Фільтр «Треба доробити»: рядки без марки чи розміру. Їх виправляють у файлі
   й розбирають знову або доповнюють уже в товарі. Фільтр «Дублі» - перевірити, що злиті
   справді однакові вироби.
4. **Застосування.** «Застосувати» створює товари з видом, характеристиками, одиницею обліку
   (кілограм для прокату), партіями для металу і серійними номерами для засобів вимірювання.
   Дублі не створюються: їхні коди 1С лишаються в протоколі розбору для звірки залишків.
5. **Залишки.** Залишки з 1С переносяться на товари за кодом з протоколу: рядок-дубль
   вказує, на який товар іти його залишку.
6. **Прайси постачальників.** Для кожного постачальника - профіль прайсу і перше завантаження
   (модуль `l10n_ua_supplier_catalog`): ціни лягають на ці самі товари за характеристиками,
   навіть коли постачальник пише назву по-своєму.
7. **Аналоги.** На товарі - «Аналоги»: заміни DIN ↔ ISO ↔ ГОСТ і марок сталі. Погоджені
   заміни для виробництва - з кнопки «Запропонувати в специфікаціях».

Якщо компанія вже веде товари в Odoo, крок 1 не потрібен: розбір «Наявні товари» розкладає
назви наявних товарів і за бажанням архівує дублі, на яких ще не було руху.
