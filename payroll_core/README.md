# payroll_core

Розрахунок української зарплати і файли ДПС без Odoo. Чистий Python, залежність одна -
`lxml` для XML. Пакет нічого не знає про базу даних і про інтерфейс: на вході дані листка,
на виході рядки з сумами.

Навіщо: найдорожча частина системи - формули і формати звітності. Вони не мають залежати
від того, у якій оболонці працює бухгалтер. Поки оболонка - Odoo. Якщо колись знадобиться
легкий сервіс, переносити треба буде оболонку, а не розрахунок.

## Як користуватися

```python
from payroll_core import Params, Slip, Employee, WorkedTime, Leaves, compute

params = Params.load("payroll_core/data/params-ua.json")
slip = Slip(year=2026, month=8, employee=Employee(name="Коваленко І. П."), wage=30000.0,
            worked=WorkedTime(work_days=21, month_workdays=21))
result = compute(slip, params)
print(result.total("NET"))       # 23100.0
```

## Що всередині

| Файл | Що робить |
| --- | --- |
| `params.py` | законодавчі числа з датою початку дії |
| `model.py` | дані листка: працівник, час, відсутності, введення, історія заробітку |
| `average.py` | середня за Постановами 100 і 1266 |
| `indexation.py` | індексація за Постановою 1078 |
| `calc.py` | правила розрахунку в порядку номерів, категорії, підсумки |
| `dps/xml.py` | каркас XML ДПС (DECLAR) і перевірка за XSD |
| `tests/golden.py` | 26 еталонних сценаріїв; ті самі числа, що й на стенді |

## Перевірка

```
python3 -m payroll_core.tests
```

Дві перевірки. Перша проганяє 26 еталонних сценаріїв: ті самі числа, що й на стенді Odoo.
Друга будує Д1 і 4ДФ з порахованих листків і звіряє їх за схемами ДПС із `dps/schemas`.
Обидві друкують PASS або FAIL на рядок і повертають код 1 при розбіжності.

Числа взяті з `docs/payroll/golden-scenarios.md`. Той самий перелік перевіряє
`scripts/payroll_check.py` на стенді. Якщо хтось змінить правило в Odoo, впаде перевірка
стенду; якщо змінять очікувані числа - впаде ця. Розійтися тихо вони не можуть.
