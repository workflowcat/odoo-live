# Банк онлайн: виписки через API і робоче місце звірки

Модуль `l10n_ua_bank_online`. Замінює ручний файл виписки на запит до банку і дає бухгалтеру
один екран: рахунки, завантаження, зарплатні платежі періоду, незвірені рядки.

## Рушій

Постачальники живуть у моделі OCA `online.bank.statement.provider` (`account_statement_import_online`).
Модуль додає дві служби і один метод розбору відповіді. Виписки, дедуплікацію за `unique_import_id`,
розклад і cron робить рушій OCA.

| Служба | Запит | Заголовки | Межі |
|---|---|---|---|
| `ua_privat` ПриватБанк (Автоклієнт) | `GET {api_base}/statements/transactions?acc=&startDate=&endDate=&limit=&followId=` | `id`, `token` | сторінки через `exist_next_page` і `next_page_id` |
| `ua_mono` Monobank | `GET {api_base}/personal/statement/{рахунок}/{від}/{до}` | `X-Token` | вікно до 31 дня, не частіше одного запиту на 60 секунд |

Дати ПриватБанку у форматі `dd-mm-yyyy`, `endDate` включно (рушій дає межу виключно, тому мінус день).
Межі Monobank - секунди Unix; довгий період ріжемо на вікна по 30 днів.
Суми: ПриватБанк - поле `SUM` плюс напрям `TRANTYPE` (`D` списання, `C` зарахування); Monobank - копійки зі знаком.
Час банку київський, тому позначку часу локалізуємо поясом постачальника (рушій вважає час без пояса за UTC).
Рядки в іншій валюті, ніж журнал, пропускаємо.

## Поля з'єднання

`ua_account` - рахунок у банку (IBAN для ПриватБанку, ідентифікатор рахунку для Monobank, «0» - типова картка).
`username` - ідентифікатор клієнта Автоклієнта. `password` - токен. `api_base` - адреса API (типово
`https://acp.privatbank.ua/api` і `https://api.monobank.ua`). `ua_demo` - демо-дані замість банку.
Кнопка «Перевірити зв'язок» робить легкий запит (`/statements/balance`, `/personal/client-info`).

Демо-режим потрібен, щоб перевірити екран і звірку без токенів: віддає десять типових рядків місяця
(надходження від покупців, аванс, зарплата, ПДФО, ВЗ, ЄСВ, аліменти) з текстами, які знаходять правила звірки.

## Екран «Банк»

Клієнтська дія `ua_bank_board`, меню «Бухоблік → Банк», пункт хабу в розділі «Бухоблік».
Дані дає `ua.bank.board.get_screen_data(year, month)`.

- ліворуч: період і рахунки (залишок, служба, кількість незвірених);
- числа місяця: залишок, надходження, списання, рядків виписки, не звірено за місяць;
- «Зарплатні платежі періоду» - ті самі рядки, що на «Зведенні» (`ua.dashboard._get_payments`), логіка не дублюється;
- «Незвірені рядки, усі періоди» - клік відкриває рядок у формі звірки OCA;
- «Виписки періоду» - назва, кількість рядків, сума рядків.

Кнопки: «Завантажити за місяць», «З початку місяця по сьогодні», «Перевірити зв'язок», «З'єднання»,
«Застосувати правила», «Звірити», «Виписки». Без з'єднання - «Підключити ПриватБанк» і «Підключити Monobank».

## «Застосувати правила»

`action_apply_rules(journal_id)` бере незвірені рядки і правила звірки (`account.reconcile.model`
з `match_label = match_regex`, їх створює `l10n_ua_bank`). Для збігу за призначенням платежу
рядку замінюємо тимчасовий рахунок банку на рахунок правила і ставимо партнера за назвою.
Після цього рядок звірений. Рядки без збігу лишаються бухгалтеру.

Правила: 661 зарплата, аванс, винагорода ЦПХ; 6411 ПДФО; 6415 військовий збір; 651 ЄСВ;
6851 аліменти і оплата ФОП-підряднику. Бухгалтер бачить і змінює їх у «Бухоблік → Правила звірки».

## Кілька банків

Один рахунок = один журнал = одне з'єднання (обмеження OCA: `UNIQUE(journal_id)`). Другий банк -
це другий журнал типу «Банк» і своє з'єднання зі своїм токеном і розкладом. Правила звірки,
проводки і звітність спільні для всіх рахунків.

На екрані: ліворуч список рахунків із залишком, службою і кількістю незвіреного, зверху сума
«разом на рахунках» і кнопка «Завантажити всі рахунки». Виписки і незвірені рядки показуються
для обраного рахунку; зарплатні платежі - по компанії.

Валютний рахунок рахується у своїй валюті: залишок береться з `amount_currency`, а рядки в іншій
валюті, ніж журнал, постачальник пропускає.

На стенді для прикладу два рахунки: «Банк (поточний рахунок)» з ПриватБанком і
«Monobank (еквайринг)» з надходженнями від карток, комісією і переказом на основний рахунок.

## Як додати ще один банк

1. Створити журнал типу «Банк» і вписати IBAN.
2. Додати службу в `_get_available_services` і гілку в `_obtain_statement_data`.
3. Написати два методи: запит до банку і переклад однієї операції в рядок виписки.

```python
    @api.model
    def _get_available_services(self):
        return super()._get_available_services() + [("ua_bank_x", "Банк X")]

    def _obtain_statement_data(self, date_since, date_until):
        if self.service != "ua_bank_x":
            return super()._obtain_statement_data(date_since, date_until)
        data = self._ua_fetch("%s/statements?from=%s&to=%s" % (
            self.api_base, date_since.date(), date_until.date()),
            {"Authorization": "Bearer %s" % self.password})
        return [self._ua_bank_x_line(t) for t in data["items"]], {}

    def _ua_bank_x_line(self, transaction):
        return {
            "payment_ref": transaction["purpose"],
            "amount": float(transaction["amount"]),          # мінус на списання
            "date": self._ua_localize(datetime.fromisoformat(transaction["date"])),
            "unique_import_id": str(transaction["id"]),      # захист від дублів
            "partner_name": transaction.get("counterparty", ""),
            "account_number": transaction.get("iban", ""),
        }
```

Решту робить рушій OCA: виписки, дедуплікація, розклад, cron, помилки в чаттері з'єднання.

## Підготовка до підключення (ключів банку ще немає)

Поки ключів немає, стенд працює на демо-даних, а справжню виписку вантажать файлом. Модуль
дає три речі, щоб перехід на API був однією дією, а не проєктом.

### 1. Чек-лист підключення

Модель `ua.bank.connect` - одна картка на банківський журнал: служба, рахунок, хто тримає
ключ, де ключ лежить (секрет Worker або поле з'єднання), через скільки місяців міняти,
дати замовлення і отримання. Усередині - кроки з виконавцем (клієнт, бухгалтер, технічний
спеціаліст) і підказкою. Кроки створюються самі за службою банку.

ПриватБанк: доступ до Приват24 для бізнесу, Автоклієнт у налаштуваннях, ідентифікатор і
токен, перелік рахунків під ключем, передача захищеним каналом, сховище, перевірка зв'язку,
розклад.

Monobank: вид рахунку (особистий чи mono Бізнес), токен у кабінеті, ідентифікатор рахунку з
`/personal/client-info`, передача захищеним каналом, сховище, обмеження (запит на 60 секунд,
вікно 31 день), перевірка зв'язку, розклад.

Стан картки: готуємо - ключ замовлено - ключ отримано - підключено. Кнопка «Створити
з'єднання» робить запис постачальника з потрібною службою і рахунком. Ключ у чек-лист не
пишемо ніколи.

### 2. Файлова виписка як робочий шлях

Модулі `account_statement_import_file` і `account_statement_import_sheet_file` стоять
залежностями. Модуль дає дві готові розмітки колонок: «ПриватБанк: виписка CSV (Приват24 для
бізнесу)» і «Monobank: виписка CSV (кабінет)». Кнопка «Виписка файлом» на екрані «Банк»
відкриває майстер імпорту з підставленим журналом.

Назви колонок узяті з типового експорту. Перший справжній файл треба звірити з розміткою і,
за потреби, виправити назви колонок у меню «Шаблони імпорту виписок».

### 3. Стан підключення на екрані

Кожен рахунок на екрані «Банк» показує свій стан: не підключено, N з M кроків, ключ є -
треба з'єднати, демо-дані, ключ працює. Той самий рядок видно в списку рахунків зліва.

## Перевірка

`scripts/bank_check.py` (42 пункти): ключі екрана, дві служби у списку, створення з'єднання дією,
завантаження в порожній місяць, захист від дублів, знаки сум, розбір відповідей обох банків
(через `odoo shell`, бо приватні методи не викликаються по RPC), дії екрана, меню для бухгалтера,
компонент у бандлі, чек-лист підключення з виконавцями, обидві розмітки файлів, кнопки
«Виписка файлом» і «Підготовка до підключення», стан підключення кожного рахунку. Тестовий
місяць прибирається наприкінці.

`scripts/demo_bank.py` готує стенд: початковий залишок на рахунку (Дт 311 Кт 441 на 01.08.2026),
реквізити демо-з'єднання, звірка виписки за правилами.

## Що лишилося

- Токени банків: чиї ключі використовуємо і де лежать (секрети Worker чи поля з'єднання).
  До цього рішення чек-лист стоїть на кроці «готуємо», а виписку вантажать файлом.
- Monobank для юридичної особи: перевірити, чи достатньо особистого токена, чи потрібен корпоративний доступ.
- Прив'язка рядка виписки до конкретного листка (зараз звірка за текстом призначення).
