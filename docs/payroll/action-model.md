# Модель дії: швидка навігація, повільна зміна

Дата: 2026-09-20. Стосується всіх наших екранів (`l10n_ua_*`).

Навігація має бути миттєвою. Зміна запису має бути видимою, зрозумілою і, де це чесно,
оборотною. Зараз дія відбувається за мить і без пояснення: користувач натиснув «Прийняти
на роботу», екран перемалювався, і що саме сталося - невідомо. Нижче правила, як це робити.

## Чотири класи дії

| Клас | Що це | Відчуття | Скасування |
| --- | --- | --- | --- |
| Огляд | Відкрити, відфільтрувати, перемкнути місяць, згорнути панель | миттєво, без діалогів | не потрібне |
| Чернетка | Створити запис, змінити поле, зібрати пакет | швидко, зберігається одразу | звичайне редагування |
| Узгодження | Підпис, ознайомлення, прийняття змін журналу | коротка пауза, видно автора | вікно «скасувати» 20 секунд |
| Проведення | Наказ, закриття місяця, подання, файл для банку | план перед дією, показ наслідків | лише виправленням, не тихим відкотом |

Правило: що більший наслідок, то повільніша дія. Огляд ніколи не сповільнюємо.

## План перед проведенням

Кожна дія класу «проведення» має метод `_plan()`, що повертає перелік того, що станеться,
одним рядком на наслідок, у майбутньому часі і людською мовою:

```
[{"text": "Наказ отримає номер з реєстру К-1", "level": "info"},
 {"text": "Створиться версія умов з 01.10.2026", "level": "info"},
 {"text": "Картку працівника буде заархівовано", "level": "warn"},
 {"text": "У вересневий листок додасться компенсація за 7 днів", "level": "info"}]
```

План показується у діалозі перед виконанням. Кнопка підтвердження називає дію словом,
а не «ОК». Якщо план порожній, дія не є проведенням і діалог не потрібен.

## Показ наслідків

Після виконання дія повертає перелік того, що сталося, у минулому часі, з посиланням на
кожен створений чи змінений запис. Екран показує ці рядки послідовно, приблизно по 400 мс
на рядок, і лише потім перемальовує дані. Разом не більше двох секунд.

Рядок наслідку клікається і веде до запису. Це та сама ціль (`target`), що й усюди.

## Вікно скасування

Дії класу «узгодження» після виконання лишають смугу «Скасувати» на 20 секунд. Скасування
виконує зворотну дію моделі (`action_unsign`, `action_reopen`), а не приховує результат.
Якщо зворотної дії немає, смуги немає теж.

Проведення вікна не має. Замість нього екран показує, як виправити: скасування наказу з
його ж форми, коригувальний звіт, сторно проводки.

## Рух

| Що | Тривалість | Крива |
| --- | --- | --- |
| Навігація, відкриття екрана | 0 | без переходу |
| Наведення, фокус | 80 мс | linear |
| Поява панелі, діалогу | 160 мс | ease-out |
| Один рядок наслідку | 400 мс | ease-out |
| Підсвічення зміненого рядка | 1200 мс, згасає | ease-in-out |

`prefers-reduced-motion: reduce` вимикає всі переходи; рядки наслідків тоді з'являються
одразу переліком. Рух ніколи не блокує роботу: під час показу наслідків екран лишається
живим, а кнопка «Пропустити» доступна.

## Контракт для клієнта

Сервіс `ua_act` у `l10n_ua_shell` дає три речі:

```js
const act = useService("ua_act");
await act.run({
    model: "ua.hire.case", id, method: "action_hire",
    plan: "action_hire_plan",        // необов'язково; є -> буде діалог плану
    confirm: "Прийняти на роботу",   // напис на кнопці підтвердження
    undo: "action_reopen",           // необов'язково; є -> смуга скасування
    onDone: () => this.load(),       // перемалювати після показу наслідків
});
```

Модель повертає з методу дії `{"done": [{"text": "...", "target": {...}}], "undo_token": ...}`
або звичайний результат дії Odoo. Якщо `done` немає, показу наслідків немає, і поведінка
така сама, як зараз.

## Де застосовуємо першими

1. «Прийняти на роботу» у Прийнятті: найбільший наслідок, п'ять створених записів.
2. «Підписано» на картці працівника: коротка дія зі скасуванням.
3. «Закрити місяць» на дошці періоду: план і перелік перешкод, без скасування.

Далі - проведення наказу, формування подання, файл для банку.

## Як користуватися (`ua_act`, реалізація 2026-09-20)

Сервіс живе в `addons/l10n_ua_shell/static/src/act_service.js` (+ `act_dialog.xml`,
`act.scss`). API той самий, що в контракті вище, з кількома деталями, яких контракт
не називав явно:

```js
const act = useService("ua_act");
await act.run({
    model, id, method,          // обов'язкові - те саме, що й для звичайного orm.call
    plan, confirm,              // необов'язкові разом: без plan діалогу немає
    title,                      // необов'язково; за замовчуванням = confirm
    undo, undoLabel,            // необов'язково; undoLabel за замовчуванням «Скасувати»
    kwargs,                     // необов'язково; kwargs самого method (напр. {reason: ...})
    openTarget,                 // (target) => void; відкриває ціль рядка наслідку
    onDone,                     // () => void|Promise; після наслідків, і ще раз після undo
});
```

- `openTarget` - контракт вище каже лише «клікається і веде до запису»; хто саме відкриває
  ціль, він не називав. Тут це явний параметр `options.openTarget`, бо в самого сервісу
  немає й не повинно бути доступу до `action`-логіки конкретного екрана (у нас це те саме,
  що сьогодні робить `openResult()` на екрані Прийняття).
- `kwargs` - контракт показує виклик без параметрів. Реальні методи (`action_reject(reason=...)`
  тощо) їх потребують, тому `run()` приймає `kwargs` для самого `method` (не для `plan` і не
  для `undo` - їх спека викликає без параметрів, і так лишилось).
- `undo_token` із прикладу відповіді моделі сервіс не читає й нікуди не передає: скасування
  просто викликає `undo`-метод на тому самому `id`, як каже розділ «Вікно скасування». Якщо
  колись знадобиться передавати сам токен - додати як kwarg до undo-виклику.
- Скільки рядок наслідку лишається на екрані після того, як усі рядки вже показані, спека не
  задає (задано лише розкриття, ≈400 мс/рядок, разом не більше 2 с). Тут це фіксовані 2.2 с
  після повного розкриття - досить, щоб прочитати й клікнути ціль, після чого панель тихо
  ховається. `onDone` кличеться одразу по завершенні розкриття, не чекаючи цієї паузи.
- Рівні плану `info`/`warn`/`crit` показані словом («інфо»/«увага»/«критично») поруч із
  кольоровою пігулкою - формат слова спека не фіксувала.
- `markChanged(el)` - експортована функція, не метод сервіса per se (хоч і продубльована як
  `useService("ua_act").markChanged` для зручності): бере DOM-вузол рядка, не id запису, бо
  який вузол «щойно змінений» - екран вирішує сам.
